# Coarse-query affine control supplement

Prospective supplement to PTCO-AFF-0.2, registered during nominal training and before any fresh held-out prediction, timing or control outcome is opened. The original fresh corpus, architecture, optimizer, selections, primary prediction/speed hypothesis and alpha-spending ledger stay as specified in the independent-confirmation contract. No new model training or task tuning is introduced.

1. **Purpose.** Measure the quality/computation frontier with both methods permitted5 and40 ms queries. The original150-episode matrix includes fine affine, fine NODE and coarse NODE. Add coarse affine so an unfavorable fine/coarse comparison cannot be mistaken for the best available use of the candidate.
2. **Entry.** Existing local CPU authorization and qualified plant/planner. All selected fresh models must be sealed before evaluation, under the unchanged nominal-only procedure. The parent design and this supplement must be committed before opening fresh outcomes.
3. **Implementation.** Add explicit coarse-control commands to the unfrozen evaluation adapter and a fourth replay card. Do not modify any frozen fitter, field model, original data or completed experiment. Reuse the same model API, action path compiler, CEM, physical cost and finite-output/fallback handling.
4. **Design.** Lagged plant,tau80 ms. The same five paired fresh training seeds2026100800..2026100804 and ten episode IDs0..9 per seed. Run each sealed affine_flow checkpoint at40 ms queries. Observation,replanning and actual command holds remain40 ms; horizon240 ms; six2D knots; CEM128 candidates,four iterations,16 elites; physical integration250 microseconds. The same fresh task/CEM streams as the parent150 episodes apply. This adds50 primary episodes; all200 episodes are retained and reported. No extra measurements or optimization variables are provided to any model. Profile40 ms query latency from the parent's existing isolated timing matrix.
5. **Commands.** `python -m poc.affine_confirmation coarse-controls`, `coarse-replay`, and `coarse-finer`. The existing aggregate/reproduce/replay export incorporates all four controller configurations, rejecting incomplete coverage. Keep separate immutable coarse batch receipts; the original150-cell batch retains its identity.
6. **Artifacts.** Exactly the parent's episode manifest,truth,action,observation,candidate,resource and failure records. Add50 main episodes,five fresh-process replays and five125-microsecond physics reruns for the first task of each seed. Include all four modes in the standalone200-clip replay. Preserve every interrupted/invalid/failed attempt.
7. **Validity.** Same paired initial state,target,CEM arrays,selected checkpoint,hardware clocks and physical costs. Independently recompute cost from true trajectories. Required complete four-configuration coordinates and hash closure. Coarse affine is neither retrained nor selected from fine-time outcomes. Apply the same replay/convergence tolerances and retain intrinsic model fallback episodes.
8. **Decision.** Add the prespecified coarse-affine versus coarse-NODE seed-mean cost contrast. The existing two contrasts (fine affine versus fine NODE and fine affine versus coarse NODE) remain unchanged. Before any positive control claim, use Holm correction across all three contrasts at the parent's current alpha_l; this is more conservative than the original two-contrast family. Report paired differences,central95% Fieller improvement intervals and per-seed/per-task results for every contrast. No minimum gain is imposed. A bounded width<=four percentage points remains the quantitative reporting target; unresolved is not equivalence. The three primary prediction/speed contrasts and their intersection-union claim are unchanged.
9. **Transitions.** Valid sufficiently precise gains/losses/unresolved near-zero effects plus reproduced evidence support the scoped final report. Wider or unstable intervals use the parent's registered precision procedure, with this additional configuration included wherever its comparison is unresolved. No new architecture/task rescue. Invalid execution triggers a minimized repair; real resource shortage is reported to the owner.

This is a measured projection,not a ceiling or promise. Update it from actual jobs and monitor remaining disk. No paid services or artificial seed/time cap.
11. **Recovery.** Use existing content-addressed locks,immutable completion markers and deterministic episode resumption. A changed producer or model is a new job,not resumption. Compare first divergent replay/physics outputs before broader reruns. Any near-threshold physics sensitivity requires the parent full affected-cell extension.
12. **Completion.** The final report compares all four measured configurations and clearly separates query latency,whole-controller time,training cost,prediction accuracy and realized control. All three control contrasts use the prospectively enlarged family. No claim of universal efficiency,real-time operation,physical-robot performance or an overall originalPTCO PASS follows from this supplement.
