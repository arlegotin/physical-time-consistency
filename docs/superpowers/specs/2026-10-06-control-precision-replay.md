# Replay of the new control precision cohort

This implements the selected-weight reproduction already required by Task 4 of `docs/superpowers/plans/2026-10-06-control-precision.md`. It adds one adapter because the original replay interface deliberately accepts only seeds 0–4. Those original interfaces, frozen scientific producers and results remain unchanged.

The owner authorized continued local execution on the current branch. This is a bounded extension of the existing replay flow: use the unchanged `poc.control_jobs` producer in fresh subprocesses, then the existing raw-evidence reader. It supplies no independent training clusters, new statistical look or evidence of model equivalence. No result is selected for replay based on whether it is favorable.

## Twelve-part execution contract

1. **Purpose.** Check that the newly evaluated selected weights reproduce their realized control behavior. Distinguish a repeatable precision result from a cache, state-restoration, environment or provenance defect.
2. **Entry.** Complete original reproduction, all twenty frozen precision checkpoints, the complete 400-episode primary precision cohort and a qualified precision result. The automatic precision supervisor must have finished its scientific stages. Local CPU/disk authorization and the pinned Python 3.11 environment remain required.
3. **Implementation.** Add only `poc/control_precision_replay.py` and `tests/test_control_precision_replay.py`, this specification, an explicit registered request and separate generated replay registries/receipts. Do not change original replay, training, model, controller, precision coordinator or inference code. No new package or general workflow engine.
4. **Protocol.** Replay episode ID 0 for every new coordinate: direct/lagged × MLP/corrected head × seeds 5–9, exactly twenty episodes at 5 ms model queries, 40 ms hardware clocks and 250 µs physics. Change only the request phase to `replication`; preserve selected weights, task seeds, initial state, target, planner and commands' parameterization. Freeze all request/source/parent hashes before executing. Read complete manifests and recompute physical costs, success and clocks from raw evidence using the existing reader.
5. **Commands.** `.venv/bin/python -m poc.control_precision_replay --dry-run`, the same command with `--prepare`, then `--resume`; focused replay tests and affected existing replay/precision tests. Prepare verifies inputs without launching an episode. Dry-run opens no new scientific outcome.
6. **Artifacts.** `config/revisions/MX-control-precision-replay-0001.json`, `config/control_precision_replay_jobs.json`, exact requests under `config/control_precision_replay_jobs/`, `reports/control_precision_replay.json`, per-child attempt logs and immutable M70 replication manifests/raw observations. The receipt records all twenty comparisons, actual resource records, original phase/checkpoint identities and hashes.
7. **Validity.** Complete unique primary coverage and exact registered seeds/coordinates; no chosen winner, substituted checkpoint, omitted failure, mutable source, partial episode or cached summary. Compare dense q/v trajectories, activation when applicable, all forty executed commands, failure classifications and realized cost. Verify environment versions and evidence/hash closure. An invalid input fails before comparisons or child dispatch.
8. **Rules.** Preserve original replay limits: maximum q difference 1e-6 rad, v difference 1e-5 rad/s, command difference 1e-6 N·m and relative realized cost difference 1e-4. Success/fallback and per-decision failure classifications must match. Report activation differences as a diagnostic. A mismatch requires reproduction diagnosis and prevents releasing the affected claim; a missing prerequisite is BLOCKED. Matching twenty selected-weight replays is a limited repeatability finding, not full PTCO PASS or fresh-training replication.
9. **Return.** All twenty pass → whole-branch review and honest limited report, or the already named precision continuation if a sign remains unresolved. Invalid evidence → repair its actual cause. Outside-tolerance behavior → named reproduction diagnostic. An external resource shortage → exact provision/resume condition. No tolerance widening or favorable duplicate selection.
10. **Resources.** The same twenty first-task coordinates in the original five-seed cohort measured 1,633.44 CPU seconds, 1,637.79 producer wall seconds, 50,340,391 artifact bytes and 410,337,280 maximum RSS bytes. These are a proxy, not promised runtime. Before dispatch, replace the projection with the actual twenty new parent records and check available disk. Preserve all evidence and failed attempts; no artificial compute cap, cloud or paid service.
11. **Recovery.** Content-derived job lock, exact dependencies, preserved child logs/return codes and atomic per-episode receipts. Compatible `--resume` independently rechecks every completed episode and resumes only missing coordinates. The existing producer handles deterministic complete-job reuse and interrupted physical episodes. Never average duplicate attempts or treat an interrupted attempt as evidence.
12. **Completion.** All twenty parent/replay pairs are hash-verified, compared within unchanged tolerances and indexed with measured resources; source and request registration are committed before execution. Record the result and review the entire implementation branch. Preserve unresolved scientific comparisons and all original reports/spending.

## Verification

Tests must reject incomplete/duplicate primary coordinates, changed source/request/checkpoint or real clocks, exploratory/replaced seeds, missing failures, nonfinite costs, incomplete trajectories, altered task identity, stale receipts and invalid completion markers. A zero error on the same weights is a replay invariant, not a new population observation. A real small MuJoCo producer fixture covers the request/manifest boundary; full scientific replay waits for the entry conditions above.
