# Hybrid component execution provenance

The reviewed scientific source is frozen at commit `97be931dcaa5d61f364397e606de17da5ce6e1e2`. `source-freeze.json` records exact all-source, executing-source, asset, runtime, recipe and binding-spec hashes and the already completed source-suite evidence. Reports and these orchestration drivers are outside `poc` and do not change scientific bindings. No historical empirical store is opened by this study.

`run_study.py` executes genuine serial calibration CLI processes. The primary invocation is `.venv/bin/python reports/hybrid_component/run_study.py primary`. It runs unfiltered prepare, collect, train, predict, decisions and one pooled time request, followed by report and verify. Every child command, exit code, monotonic wall duration, process CPU duration, start/end chronology, thread environment and executed driver hash is retained in its own execution record. The inclusive CLI durations are a separate resource view and cannot be added to overlapping producer ledgers.

The actual initial driver completed all six empirical stages, then failed before launching report because the destination path was used verbatim in the log filename. `run_study_initial.py` preserves its exact executed bytes and hash; `orchestration_failure.json` and `orchestration_failure_traceback.txt` preserve the failure and its unmeasured support-wrapper tail. Only filename separators were sanitized in the corrected driver. Report ran through a genuine separate CLI invocation with no repeated empirical stage. After the fresh replicas and numerical checks, one final primary raw verification ran through `run_study.py stage verify`; the controller explicitly consolidated the post-report/final verification into this one complete scan. Replica verification remains separate. The command records distinguish original and corrected executed driver hashes.

The fresh-root invocation is `.venv/bin/python reports/hybrid_component/run_study.py replica`. It prepares a separate full hybrid recipe, independently collects all 600 session-1 segments, and fits session 1 / budget 30 / initialization 0 for each of the three coefficient-family models. This is reproduction of predeclared coordinates, not another scientific draw or an additional independent calibration session.

`.venv/bin/python reports/hybrid_component/run_numerical.py` runs the archived `replication_driver.py` in a fresh process, then raw-verifies the replica root. The numerical driver is adapted from the prior pilot's support driver, using the hybrid recipe, new model identities, calibration session 1 and evaluation seed session 1. Its explicit normalization of output-root bindings permits only the intended root difference. It sets the frozen one-thread deterministic execution settings, checks complete collected/evaluation arrays and selected tensors/validation, and replays first/last prediction and full candidate-bank products, retained numerical envelopes, decisions, statuses, selections, regret and work/query logs under all four main partitions. Designated first/last trajectories receive independent three-grid prediction/decision truth replay, with retained adaptive grids replayed where required. Original prior drivers and results are preserved.

`audit_driver.py` copies exact command records, logs, prepared manifests and source/asset hash maps into this report directory; archives primary and replica resource attempts separately; and hashes exported artifacts. It uses top-level producer attempts once, excluding nested parent/child overlap. Numerical replica resources and inclusive CLI records remain separate from primary training and evaluation totals. Calendar timestamps establish chronology only. The frozen post-commit observation fix excludes its own ledger-write observations; reported producer totals exclude post-producer finalization and are not a complete end-to-end commissioned hardware cost.

The fixed headline is session-wise eligibility at budget 30 seconds / main step 40 milliseconds, then at least 25% pooled complete-scorer median savings and p95 no worse than the fastest acceptable alternative. Other budgets/partitions and same-weight propagation are diagnostics. Three sessions support an exploratory simulator study, not powered confirmation, a physical deadline or hardware commissioning. All failed and limited fits, unresolved truth/feasibility and unsuccessful alternatives remain retained.
